## 决策依据与论证

### 1. MBBDB 不应按单一船名或年代裁剪

[MBBDB 对照](step13_mbbdb_crosswalk.md)给出的当前规模是 3,970 个唯一航次，本地按归一化航次号匹配 91 个，未匹配到本地同号航次的目录差集为 3,879 个、约 1,169,184 个文件和 43.8 TB。43.8 TB 是 MBBDB `fileSizeSum` 的合计，未去重且包含 RAW 类目；它不是处理后产品体量，也不包含 91 个已匹配航次内部的缺件。目录差集集中在 2000 年代和 2010 年代；若按船整批获取，Ventresca 单船约 6.74 TB，OKEANOS EXPLORER、HENRY B. BIGELOW、Celtic Voyager 等也都是大体量来源。相反，一些 1980 至 1990 年代的 NOAA 船在表中因四舍五入显示约 0 TB，但几乎全部有同号 Trackline 单波束。

这些数字支持按用途和增量覆盖裁剪，不支持按“老船便宜”或“新船数据新”直接下单。建议采用以下筛选顺序：

1. 用 MBBDB 的实际航迹几何与六个下游海区求交，不用船名或包围框命中替代实际重合。
2. 在相交航次内，计算相对现有严格多波束层新增的 1′ 格子。只重复现有多波束格的航次排后。
3. 优先保留本地没有同号 Trackline 单波束的航次，它们提供新的空间与仪器来源。另保留少量本地已有同号单波束的航次，用于比较同航次多波束与单波束，而不是把 1,671 个同号航次全部下载。
4. 在科学价值相近时，按下载字节数和预期新增格子数排序。逐船和逐年代设上限，防止一个大船队或一个时期占满批次。
5. `fileCount` 为 0 或空的 71 个航次不进入订单。

当前缺少第 1 和第 2 步的交集结果。因此，本备忘录不列出未经证据支持的新增 Survey ID。当前可执行的第一批是对已经存在的 24 个平台树航次做完整性分类：`AR15`、`AR23-02`、`AR30-01`、`AR30-04`、`AR40`、`AR41`、`AR42-02`、`AR45`、`AR59`、`AR66-A`、`AR66-B`、`AR9-03`、`CNTL01RR`、`CNTL02RR`、`EW9801`、`EW9905`、`FK006B`、`FK006C`、`FK008`、`HLY1102`、`HLY1401`、`HLY1402`、`HLY1403`、`HLY20TB`。这些 ID 已从 3,879 个目录差集中扣除，但这不表示航次内部文件齐全。完成完整性分类后，需要重报“完整本地航次、缺件航次、未分类航次”，并把缺件续传与新增 Survey ID 订购分开决定。

完整性分类后，先用目录已有几何筛选六海区，再处理命中且完整的航次。命中但缺件的航次进入续传候选；不命中六海区的航次不因文件已经在盘上就自动加工。下一批新增 Survey ID 仍应设置两个硬条件：至少命中一个六海区，并能增加现有严格多波束 1′ 覆盖。没有满足条件的航次时，新增订购继续为 0。满足条件时，再按单位新增格子的下载与处理成本确定批次大小，不先承诺航次数或 TB 数。

### 2. 多波束处理入口的条件与范围

[数据产品规范](../../docs/数据产品规范与下游接入.md)规定，新船测来源必须同时产出 L1 点、L2 格子和 L3 航线来源登记，三层少任何一层都不能更新交付产品。全球格网在同一格同时存在两类数据时，以严格多波束作为 `depth_m` 主值，单波束只留在诊断列。多波束和单波束在产品中承担的角色不同。

[最终数据轮报告](/mnt/data2/06-Projects/15-swot_feature_physics_bathy/reports/15_final_data_round.md)说明，在固定的六海区开发比较中，加入最终单波束后，inner-validation pooled block-equal RMSE 从 89.667 m 增至 104.236 m，变化为 +14.569 m。pseudo-outer pooled region-equal RMSE 虽从 191.888 m 降至 153.715 m，但六区中五区变差，合并改善由 `lon068_lat018` 的 -238.045 m 主导。该证据不支持继续以“增加单波束数量”作为模型改进路线，也没有测试新增严格多波束是否有收益。

建议先完成完整性与六海区几何筛选。存在一个完整或值得补全的命中航次时，再建设限定范围的原始多波束处理入口：

- 输入只接收命中六海区、且下载日志和目录清单都支持完整状态的航次。`.part`、只有目录记录或来源身份不清的文件不进入处理。
- 实施前先扩展[数据产品规范](../../docs/数据产品规范与下游接入.md)和 L3 schema：明确一个原始声呐文件如何映射到 `track_id`，航次与航线分别处在哪个粒度，以及 MBBDB 的 `source_type`、`source_archive` 和原生质量标志如何记录。现行 `nc|xyz` 文件名和 `ncei_nc|ncei_xyz` 来源枚举不能直接表示原始多波束。
- MB-System 负责从受支持的原始格式提取逐测深记录和来源内标志；之后复用现有多波束点标准化、1′ 格化和来源登记结构。仓库已有[固定版本的来源内处理实现](../code/scs_confirmation/process_scs_v2_stage_c_source_internal.py)，新入口应复用其已确认的字段语义，不复制成另一套规则。
- 每条定义后的航线独立产生 L1 和 L2，每个来源侧写入 L3；失败航线不阻塞其他航线，也不能以三层不齐的结果更新交付产品。
- 严格层只接收满足现有来源、坐标、深度符号、有效标志和代表深度要求的格子。原始多波束下载成功不等于进入严格层。
- 完整子集处理完成后，先报告全球新增严格格数、六海区新增严格格数和与现有严格层的重合，再决定是否做下游开发集比较。不开封 sealed outer evaluation。

这个决定不包括为 43.8 TB 设计并行下载、集群调度或全库重处理。若命中六海区的完整子集不能产生可追溯的严格格子，停止新增 MBBDB 订购，修正处理入口或放弃对应格式。若 24 航次没有任何六海区命中，本轮不建处理入口；是否为全球覆盖单独建设，需要另列科学用途、资源预算和停止条件后再决定。

### 3. 已下载数据的处理边界

[Round-2 记录](step11_archive_gap_report.md)显示，平台树共有 24 个航次、3,179 个成功文件和 149,051,800,841 bytes，约为 149.1 GB（十进制）或 138.8 GiB；实际现存占用至少为此值，另加 `.part`。另有 169 个 R2R 处理后归档；两类资料不应混作同一种原始 MB-System 输入。五个 `.part` 文件分别位于 `HLY1401`、`HLY1402`、`AR30-04`、`AR42-02` 和 `HLY20TB`；目录扫描还确认 `AR30-04`、`AR45`、`AR66-A` 没有取全所列文件。合并去重后至少 7 个航次已知不完整，其余航次仍需目录侧核对后才能标为完整。

建议保留现有目录和 `round2_download_log.parquet`，不移动、不覆盖原始文件。中间点和格子产品按定义后的航线写入新路径；只有三层齐全且通过严格层规则后，才建立带新轮次标签的交付目录。旧的严格多波束层和下游固定轮次保持不变。

磁盘代价不能只按 149.1 GB 原始量估算。逐点标准化文件和 1′ 格子会增加额外空间，MB-System 解压或临时输出也可能产生短时峰值。开始实现前需要给 24 航次做文件格式与空间预算，但不需要再下载数据。

### 4. JAMSTEC 计数差异的处理顺序

[全球渠道盘点](step12_channel_inventory.md)和[MBBDB 对照](step13_mbbdb_crosswalk.md)已经解释了 255 与 649 的主要差异：255 只对应第一份源 zip；全语料有 763 个 subzip、649 个 `cruise_id_guess`，以及约 5,100 个活跃 `.dat` 文件。这里仍有一个待处理问题：649 是现有推测航次 ID 的唯一数，不等于已经完成两份源包的规范化航次身份审核。

建议把这项工作列为 JAMSTEC DARWIN 外部差集的必要前置项，但不把它设为 NCEI MBBDB 处理的前置项。交付物只需一张映射表：每个 subzip、原始航次字段、规范化航次 ID、平台、时间范围、数据类型和异常说明。完成后固定三个不同计数的含义，不再用“JAMSTEC 本地有 255 航次”描述全语料。

### 5. 外部渠道只排元数据盘点

[全球渠道盘点](step12_channel_inventory.md)确认了来源发现空间，但没有得到 EMODnet、MGDS 或 PANGAEA 可去重后的航次数与字节数。现在新增下载会同时遇到三类未知：与 NCEI/JAMSTEC 的重复程度、能否取得原始测点、逐数据集许可。

建议顺序如下：

1. EMODnet/SeaDataNet CDI：只导出调查级元数据，至少保留 provider、cruise、instrument、时间、空间范围、access restriction 和下载状态；不提交批量申请。它覆盖 65 个以上提供方，最适合先量化候选池。
2. MGDS/GMRT：访问链路恢复后，导出 cruise 与原始 swath/track 目录，并先与 NCEI 的 Lamont-Doherty、R2R、Scripps 和 WHOI 航次去重。当前访问失败时不反复尝试。
3. PANGAEA：最后做 DOI 级候选清单，以 cruise、vessel 和 DOI 去重。关键词检索命中数不能作为船测规模。

这三项排在 JAMSTEC 身份映射、MBBDB 24 航次审核和首个合格航次处理之后。若 24 航次没有合格对象，则不等待处理入口，直接按此顺序开展外部元数据盘点。外部盘点的停止条件是得到可去重候选清单和访问/许可状态；在候选清单经过六海区空间筛选前，不下载数据。

### 6. NCEI 订购故障应立即报告

本轮新增事实是：706 条单波束订单 `#609993` 以及三次参数变体均在 NCEI 内部 `catalogPost` 阶段返回 HTTP 500；MGD77T、XYZ 和 selections 变体均已尝试。不同请求形式在同一内部阶段失败，强烈支持服务端异常，足以提交故障报告；邮件仍应提供按官方示例构造的最小请求，以排除四次请求共享字段的问题。邮件应附：

- 订单号 `#609993`，首次提交和三次变体测试的 UTC 时间；
- 每次请求选择的格式、selections 和 Survey ID 数量，不附账户令牌；
- `catalogPost` 的 HTTP 状态、响应正文、请求标识或相关 ID；
- 一条最小化失败请求，便于 NCEI 复现；
- 静态 MGD77T 路径抽样 5/6 命中，当前正用于下载 706 条，但它不能替代订购服务对缺失项和格式变体的处理；
- 请求 NCEI 确认 `#609993` 是否会继续执行，还是已经失败且需要重新提交。

代理流量状况不应写成 NCEI 服务故障证据。美国和日本出口耗尽、德国出口 `2085` 约 1 MB/s、香港出口 TLS 被 NOAA 中断，描述的是本地到 NOAA 的访问条件；邮件只报告不依赖这些出口差异也能复现的 `catalogPost` 500。
