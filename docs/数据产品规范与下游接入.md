## 1. 三层中间产品

新来源的船测数据必须三层全部落地（L1 点、L2 格子、L3 登记进航线来源清单），之后才允许再生成交付产品（偏差表、处置表、最终单波束层、全球网格）。三层缺任何一层，交付产品不更新。

通用约定：

- 深度一律为**正向下**的米数（数值越大水越深）。
- 空间格子为 1 弧分（1/60 度）；`lon_bin` / `lat_bin` 是格子编号，`lon_center` / `lat_center` 是格心经纬度，`cell_id` 由两个编号拼成。
- 每条航线一个 parquet 文件，文件名 `<track_id>__<nc|xyz>.parquet`（`track_id` 是去扩展名的原始文件名，`nc` / `xyz` 记录来源侧）。
- 单波束与多波束分支分目录存放，列结构相同。

### 1.1 L1 点：每条航线一个点文件

| 项 | 内容 |
|---|---|
| 单波束 | `ncei/derived/singlebeam/points_raw/`（7,215 个文件：1,850 个 nc + 5,365 个 xyz） |
| 多波束 | `ncei/derived/multibeam/points_raw/`（17 个文件） |
| 质检变体 | `ncei/derived/singlebeam/points_checked/`（5,365 个文件，在 raw 之上追加质检列） |

`points_raw` 列（17 列，两类分支一致）：

| 列 | 类型 | 含义 |
|---|---|---|
| `source_type` | string | 来源侧：`ncei_nc` 或 `ncei_xyz` |
| `track_id` | string | 航线标识，跨层的主键 |
| `point_index_in_track` | int64 | 点在航线内的序号（无时间戳的航线以此为准） |
| `time` | timestamp[ns] | 时间戳；xyz 来源为空 |
| `lon_raw` / `lat_raw` | double | 原始经纬度（标准化前） |
| `lon` / `lat` | double | 标准化后经纬度 |
| `depth_raw` | double | 原始深度值（符号未统一） |
| `depth_m_positive_down` | double | 标准化深度，正向下，米 |
| `elev_m` | double | 高程（与深度符号相反的镜像） |
| `gobs` / `faa` | double | 观测重力、自由空气异常（无则空） |
| `source_completeness` | string | `nc_only` / `xyz_only` / `nc_xyz_intersect` |
| `instrument_class_pred` | string | 分类器判定的 `singlebeam` / `multibeam` |
| `standardization_version` | string | 标准化脚本版本 |

`points_checked` 追加列（6 列）：`valid_lon`、`valid_lat`、`valid_depth_pos`、`valid_depth_max`、`valid_core_fields`、`point_check_pass_basic`（全部 bool，逐点质检结果）。

新数据入库要求：L1 必须带齐上表 17 列；深度符号按 L3 清单里的 `depth_sign_raw` 逐航线判断，不得假设全局符号约定。

### 1.2 L2 格子：每条航线每格一行

三个变体按加工深度递进，列结构前者是后者的前缀：

| 目录 | 内容 | 文件数 |
|---|---|---|
| `ncei/derived/singlebeam/file_cells_1min/` | 原始格子统计 | 5,365 |
| `ncei/derived/singlebeam/file_cells_1min_adjusted/` | 追加航线偏差改正三列 | 5,365 |
| `ncei/derived/singlebeam/file_cells_1min_final_r2/` | 最终层：应用/撤回改正并写入航线处置（任务 09-03-global-sb-final-product 产出，目录名带轮次标签 `_r2`） | 5,365 |
| `ncei/derived/multibeam/file_cells_1min/` | 多波束分支的原始格子统计 | 17 |

基础列（23 列）：

| 列 | 类型 | 含义 |
|---|---|---|
| `track_id` | string | 航线标识 |
| `source_type` | string | 来源侧 |
| `source_completeness` | string | 来源侧拼接状态 |
| `instrument_class_pred` | string | 单波束 / 多波束判定 |
| `branch` | string | 分支名（`singlebeam` / `multibeam_ncei`） |
| `cell_id` | string | 格子标识 |
| `lon_bin` / `lat_bin` | int64 | 格子编号 |
| `lon_center` / `lat_center` | double | 格心坐标 |
| `n_points_pass` | int64 | 通过点级质检的点数 |
| `n_unique_triples` | int64 | 去重后的 (lon, lat, depth) 三元组数 |
| `duplicate_ratio` | double | 重复点比例 |
| `median_depth_m` | double | 格内深度中位数（主值） |
| `mean_depth_m` / `std_depth_m` | double | 均值、标准差 |
| `min_depth_m` / `max_depth_m` / `range_depth_m` | double | 极值与极差 |
| `iqr_depth_m` | double | 四分位距（格内离散度的稳健度量；本层没有 NMAD 列，NMAD 在航线层产品中计算） |
| `manual_review_flag` | bool | 是否命中人工复核规则 |
| `median_depth_m_all_points` | double | 不剔除点的中位数（对照用） |
| `median_depth_m_unique_triples` | double | 只用去重点的中位数（对照用） |

`file_cells_1min_adjusted` 追加 3 列：`track_bias_m`（该航线估计的偏差，米）、`bias_applied`（bool，是否已施加改正）、`bias_n_support`（int64，估计偏差所用参照格子数）。

`file_cells_1min_final_r2` 再追加 1 列：`track_disposition`，取值 `correct` / `keep_raw` / `revert_to_raw` / `reject` / `flag_large_unapplied_bias`。最终层**不删任何行**，消费方自己按第 4 节的规则过滤。该列的判定规则（先改正、后按改正后一致性判处置；时间倒退和无有效格子的航线直接拒收）由任务 `.trellis/tasks/09-03-global-sb-final-product/prd.md` 固定，其产出 `ncei/derived/sb_track_quality_global/track_quality.parquet`（每航线一行，含处置、阈值、理由）是处置依据的查询表。

另有一个跨航线聚合层（诊断用，不是交付产品）：

- `ncei/derived/singlebeam/cells_1min/branch=singlebeam/lat_band_10deg=<n>/part-*.parquet`
- `ncei/derived/multibeam/cells_1min/branch=multibeam_ncei/lat_band_10deg=<n>/part-*.parquet`

每个 1 弧分格子一行，把落在该格的多条航线聚合（`n_tracks`、`n_track_cells`、`median_depth_m`、各来源计数 `n_source_ncei_nc` / `n_source_ncei_xyz` / `n_source_mrar_zhoushuai` 等 30 列）。`lat_band_10deg` 是 10 度纬度带分区（南纬为负）。

### 1.3 L3 航线来源清单

- 数据：`ncei/manifests/trackline_source_manifest.parquet`（另有一份 TSV 镜像 `trackline_source_manifest.tsv`）
- 逐列语义文档：`ncei/docs/trackline_source_manifest_schema.md`
- 生成脚本：`ncei/code/01_build_trackline_source_manifest.py`

26 列，一行一个"来源侧"（同一 `track_id` 的 nc 和 xyz 两侧各占一行）。列分五组：

| 组 | 列 |
|---|---|
| 识别（5） | `track_id`、`source_type`、`source_completeness`、`source_path`、`source_archive` |
| 几何（7） | `n_points`、`bbox_lon_min`、`bbox_lon_max`、`bbox_lat_min`、`bbox_lat_max`、`bbox_area_km2`、`point_density_km2` |
| 字段可用性与深度符号（7） | `has_time`、`has_depth`、`has_gobs`、`has_faa`、`depth_sign_raw`、`depth_min_raw`、`depth_max_raw` |
| 分类（5） | `instrument_class_pred`、`classification_rule`、`classification_review`、`review_reason`、`manual_override` |
| 出处（2） | `source_author`、`survey_id` |

约定（详见 schema 文档的"Stable contract notes"）：加列允许；改名或删列是破坏性变更。`depth_sign_raw` 的 5 个取值是封闭枚举。

新数据入库时，新航线必须先出现在本清单，后续各层用清单里的 `track_id` 和 `instrument_class_pred` 分流。

## 2. 全球网格产品（规格已定，产品尚未生成）

本节产品**尚未生成**，由后续任务按此规格产出；规格现在固定，是为了下游可以先行按第 4 节的等价规则取数。

| 项 | 规格 |
|---|---|
| 路径 | `ncei/derived/global_grid_1min_r2/`（目录名带轮次标签；下一轮为 `_r3`，依次递增；旧轮次目录保留不删） |
| 组织 | hive 分区 `lat_band_10deg=<n>`（10 度纬度带，南纬为负），每分区 `part-*.parquet` |
| 粒度 | 一行一个 1 弧分格子，全球 |
| 输入 | 严格多波束格 `ncei/derived/validation_cells_1min/strict_primary_multibeam_cells.parquet`（列 `cell_id`…`representative_depth_m` 等，2,398,774 行）；最终单波束层 `ncei/derived/singlebeam/file_cells_1min_final_r2/` 过滤 `track_disposition != 'reject'` |
| 清单 | 目录下 `product_manifest.json`：`created_at`、`created_by`、`source_paths`、**每个输入文件的 sha256**、总行数、轮次标签。现有产品的 manifest（如 `ncei/derived/sb_track_bias_global/product_manifest.json`）记路径和时间但不记哈希；本产品从第一版起必须记哈希 |

列规格：

| 列 | 类型 | 含义 |
|---|---|---|
| `cell_id` | string | 格子标识，与其他产品同构 |
| `lon_bin` / `lat_bin` | int64 | 格子编号 |
| `lon_center` / `lat_center` | double | 格心坐标 |
| `depth_m` | double | 主值，正向下米 |
| `source_layer` | string | `multibeam_strict`（严格多波束）或 `singlebeam_final`（合格单波束） |
| `sb_median_depth_m` | double | 该格合格单波束格子的中位数；无合格单波束时为空。两层都有的格子主值取多波束，单波束值保留在此诊断列 |
| `n_tracks_sb` | int64 | 该格合格单波束格子来自几条航线 |
| `round` | string | 轮次标签（如 `_r2`），与目录名一致 |

取值规则（两层规则，与 `docs/单波束数据质量处理与下游实验结论.md` 第 4 节的表述一致）：一个格子有严格多波束代表深度就用它；没有的格子用该格合格单波束（`track_disposition != 'reject'`）格子的 `median_depth_m` 中位数；两者都有时主值取多波束、单波束值进诊断列。

GEBCO 的既定边界在本产品同样适用：GEBCO 只能作为分层诊断的参照，不得作为任何数据筛选或拒收的门槛，也不进入 `depth_m`。

## 3. 单波束生产决策：只维护一个最终层

交付给下游的单波束产品只有一个：`ncei/derived/singlebeam/file_cells_1min_final_r2/`。`file_cells_1min/`（原始）和 `file_cells_1min_adjusted/`（只改正）保留在盘上、可由脚本复现（`ncei/code/25_global_singlebeam_track_bias.py` 等），但不作为产品维护，轮次更新时不通知下游，下游也不得引用。

证据（`ncei/docs/step10_sb_interpolation_holdout_report.md`，2026-09-03，GMT surface 纯插值留出试验，六个海区等权合并 RMSE）：

| 方案 | 合并 RMSE（米） |
|---|---:|
| 只用多波束 | 1,840.89 |
| 加改正后单波束 | 731.12 |
| 改正后再剔除拒收航线 | 673.19 |

结论：在多波束训练点稀少或缺失的区域，单波束提供有效的水深约束；剔除规则优于只改正。分区方向仍不一致（六区中有四区加单波束后误差上升），所以下游引用时应引用合并数字并说明分区保留意见，报告原文有逐区数字。

## 4. 下游消费契约

**读什么**：

1. 首选：全球网格产品（第 2 节，待生成）。生成之前，下游自己按下述规则直接读两个输入并做同样的合并。
2. 严格多波束：`ncei/derived/validation_cells_1min/strict_primary_multibeam_cells.parquet`，深度列 `representative_depth_m`。
3. 单波束：`ncei/derived/singlebeam/file_cells_1min_final_r2/`，深度列 `median_depth_m`。

**过滤规则（一句话）**：单波束一律过滤 `track_disposition != 'reject'`；有严格多波束格子的位置用多波束，其余位置用过滤后的单波束。

**轮次固定**：交付产品的目录名带轮次标签（`_r2`、`_r3`…），目录内的 `product_manifest.json` 记生成时间和输入哈希。下游要固定一轮，就同时记录（a）所读目录的轮次标签，（b）该目录 manifest 里的输入哈希。旧轮次目录不删，固定旧轮次的下游不受新轮次影响。

**下游 run manifest 的硬性要求**：每次使用本仓库产品的下游运行，其运行清单必须记录产品轮次标签和所读产品文件的 sha256。下游仓库 `15-swot_feature_physics_bathy` 已经在 `outputs/*/manifest.json` 里这样做（如 `20260902T175753Z-nested-pseudo-outer-sb-nested_pseudo_outer_sb/manifest.json` 的 `sha256` 字段），本节把它从现状升格为要求。

**禁止事项**：

- 不得引用无轮次标签的中间层（`file_cells_1min/`、`file_cells_1min_adjusted/`、`cells_1min/`）作为产品输入。
- 不得删除 `file_cells_1min_final_r2/` 中的 `reject` 行来"瘦身"——拒收信息本身是证据。
- GEBCO 不得进入任何筛选或拒收判定。

## 5. 消费者登记：`consumers.yaml`

仓库根目录的 `consumers.yaml` 是下游消费者登记表。字段：

| 字段 | 含义 |
|---|---|
| `repo_name` | 下游仓库名 |
| `repo_path` | 下游仓库绝对路径 |
| `product` | 消费的产品（如 `global_grid_1min_r2`、`file_cells_1min_final_r2`） |
| `round` | 固定的轮次标签（如 `_r2`；跟随最新轮次则写 `latest`） |
| `consuming_agent_or_workspace` | 接收新轮次通知的 paseo agent 或 workspace 名 |
| `registered_at` | 登记日期 |

如实说明：登记是约定，不是强制。本仓库没有任何机制阻止未登记的仓库读数；未登记的实际后果是第 6 节的新轮次通知不会送到它那里。接入的最后一步就是在此文件加一条记录（当前文件里有一条注释掉的示例条目可参照）。

## 6. 新一轮数据的更新与通知流程

新船测数据到达后，按以下顺序执行（步骤与脚本的对应关系以 `README.md` 的"Adding new ship data"一节为准，该节由任务 09-03-global-sb-final-product 维护）：

1. 原始文件按来源放入 `ncei/tracklines_nc/`、`ncei/tracklines_xyz/` 等目录，更新对应 `SOURCE.md`。
2. 重跑管线：`01` 建航线来源清单 → `02–06` 标准化与点级质检 → `07–08` 格子 → `25` 航线偏差 → `26` 交叉点 → `30` 全球处置。新航线以清单中新增的 `track_id` 识别。
3. 核对三层齐全（第 1 节），任何一层缺新数据则停止，不更新交付产品。
4. 交付产品写入**新的轮次标签目录**（如 `_r3`），不覆盖旧目录；`product_manifest.json` 记时间与输入哈希。
5. 更新本页受影响的路径和 `README.md` 产品清单。
6. 对 `consumers.yaml` 里登记的每个 agent / workspace，通过 paseo 发一条新轮次通知（新目录路径、轮次标签、输入哈希、与上一轮的差异摘要）。
7. 下游收到通知后自行决定是否切换；切换后在它自己的 run manifest 里记录新轮次与哈希（第 4 节要求）。
