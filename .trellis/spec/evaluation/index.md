# Evaluation Guidelines

Use the smallest comparison that helps answer the question. When two cases
are compared, state what stayed the same, what changed, the data used, and the
units of the reported number. Check a data or input assumption when getting it
wrong could silently change the result; let ordinary errors fail normally.

A comparison should distinguish the explanations at issue in the current
question. Add a case when the results so far cannot distinguish them or the
added case could change the conclusion. When the question is answered, record
the result and stop.

If a model or parameter was chosen using data, say which data were used for
that choice and which data produced the reported number. Use a separate
evaluation set when the question needs an estimate on unseen data.

Repeat a run or report variation when the question is about stability or a
difference between conditions. Describe a single run as one observation and
match the precision of the claim to the information in that run. When
conditions share data or folds, report the paired per-fold differences; a
single run per condition supports a description, not a ranking.

Record the actual number, condition, metric definition, and any output path
needed to rerun it. Report an unexpected, negative, or null result with its observed value.
